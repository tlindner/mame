GIME-X
======

The ``coco3x`` system models a Color Computer 3 fitted with Gary Becker and
Ed Snider's GIME-X.  It uses the existing GIME core with the extensions in the
*GIME-X Installation and User Guide*, dated 22 April 2020:

https://drive.google.com/file/d/1Ig3bDV8Scv9jB1mQwxSIoqn8Bqp-kFPZ/view

The programming reference is on pages 8-12.  The local CoCo Hardware Reference
by Tim Lindner provides an additional register-map cross-reference.

Implemented extensions
----------------------

* Eight-bit MMU registers, with 128 KiB, 512 KiB and 2 MiB RAM configurations.
* Independent 21-bit DMA source/destination addresses at FFE1-FFE6,
  read/write auto-increment controls at FFE7 and the byte/word port at FFE8-FFE9.
  Addresses wrap at 2 MiB; smaller installed memories mirror.  With increment
  disabled, FFE9 accesses the byte following the programmed address.  With
  increment enabled, each transferred byte advances its respective address.
* The A5 write to FFD9 selects 2.86 MHz.  Other FFD9 writes select 1.78 MHz;
  FFD8 selects 0.89 MHz.  The guide's preceding reference to FF9D for selecting
  1.78 MHz appears to be a typo; the SAM speed addresses are FFD8/FFD9.
* Nine-bit RGB palettes at FFB0-FFBF.  The first write supplies R2/G2/B2 and
  R1/G1/B1 in the usual six-bit GIME format and clears R0/G0/B0.  A second write
  with bit 7 set supplies R0/G0/B0 in bits 5-3.  Writing an index to FFE0 copies
  palette zero into that entry of the separate 256-colour palette.
* FF98 bit 6 and FF99 HRES=000/001 select 320/640 bytes per row.  CRES=11
  selects eight-bit indexed pixels.  This supports 640x225 in 16 colours,
  320x225 in 256 colours, and 640x112.5 in 256 colours (LPR=011).
* SAM-selected SG8, SG12 and SG24 memory progression, and optional SG6 decoding.
* VGA line doubling, the scanline button, and artifact/SG6 button.

The default display is RGB/VGA.  F6 represents the artifact/SG6 button and F7
represents the scanline button.  In legacy text mode with FF22 bit 4 set, F6
toggles SG6 versus lowercase text.  Otherwise it cycles the artifact choices.

Shared implementation and limits
--------------------------------

``gime_video`` contains the common graphics shifter, semigraphics pixel
selection, row-width decoding and palette-write decoding.  CoCo3FPGA 4.1 uses
these operations while retaining its HDL-specific register decoding, 12-bit
palette, memory controller and 25 MHz VGA timing.  Its bandwidth selector is
not interchangeable with the GIME-X selector.

The GIME-X model retains the original GIME core's beam and interrupt timing.
Its VGA display is generated by doubling source lines; it is not a simulation
of the FPGA's fetch pipeline or analog output circuitry.  The MAME artifact
filter approximates the hardware's MESS-style option, and the simple option
uses a four-colour pair decoder.  The F1/reset NTSC phase-selection sequence is
not modelled.  Undocumented reads of the new write-only registers retain the
underlying ROM data, including FFEF; no firmware version is invented.  The
system is consequently marked with imperfect graphics and timing flags.

Regression test
---------------

``tests/trs/coco3x.lua`` is an external Lua integration test, independent of
``scripts/src/tests.lua``.  From the repository root, run it with::

    ./mamed coco3x -console -debug -video none -debugger none -sound none \
        -ram 2m -autoboot_delay 1 -autoboot_script tests/trs/coco3x.lua

It checks both MMU tasks across all 256 banks, the FE page, DMA word/byte
transfers and address rollover, all three new video modes, palette programming,
save/load, scanlines, SG6/8/12/24, and CPU speed ratios.  It prints a PASSED or
FAILED result and exits.  Use the normal CoCo 3 and GIME ROM sets.
